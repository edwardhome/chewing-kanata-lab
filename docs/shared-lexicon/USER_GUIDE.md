# 跨平台共用個人詞庫使用者手冊 (Windows / Mac)

> **重要狀態聲明**：
> 本功能目前處於**開發階段（In-Development），非已發布功能**。基準對齊 AI-Bopomofo（Mac）與 AI新酷音 1.1.0（Windows）。現行 1.1.0 正式版本不包含此跨平台共用詞庫功能。

---

## 1. 核心理念與隱私安全邊界

1. **嚴格禁止存取與同步私人內部資料庫**：
   - 跨平台共用詞庫**絕不讀取、變更、覆寫或自動同步**各平台執行中的內部詞庫（如 Windows 正式新酷音之 `%APPDATA%\Chewing\userphrase.sqlite` 或 Linux/Mac 本機 SQLite 詞庫）。
   - 不同步或傳播各平台內部動態學習之選字分數、敲鍵歷史或日常未送出緩衝區。
   - 零雲端依賴：完全以使用者主動操作之離線交換檔為媒介，絕不進行背景靜默上傳。

2. **手動交換、純記憶體預覽與本機自主授權原則**：
   - 跨裝置詞庫移轉完全仰賴使用者**手動匯出與手動匯入**完成的 UTF-8 JSON 交換檔（`ai-bopomofo.lexicon` 格式）。
   - 來源檔案中的審核標記（如 `status: approved` 或 `user_confirmed: true`）僅供本機參考，**絕不能直接替目標機器授權部署**。
   - **純記憶體預覽與寫入授權**：本機載入外部檔案時**僅在記憶體中進行預覽解析**；在使用者於本機介面完成明確核准前，**絕不進行任何磁碟寫入，亦不賦予任何部署授權**。
   - **被拒絕項目排除與快照保留**：無論是在來源端標記拒絕或於本機審核時被拒絕（rejected）的條目，**一律排除於候選字清單之外**，不參與組字；但經本機確認建立快照時，這些被拒絕或觀測到的項目與元資料可完整保留於快照記錄中，供後續匯出或重新檢視。
   - 所有外部匯入項目在進入本機候選擴充前，必須在設定介面進行本機預覽、逐筆審查並獲得使用者明確授權核准。

## 2. 操作工作流程

### 2.1 匯入預覽與審核流程 (Import & Local Approval)
1. **載入檔案**：於設定介面選取副檔名為 `.json` 的共用詞庫交換檔案（僅讀入記憶體解析）。
2. **語意與結構解析**：系統解析 JSON 內容，嚴格檢查版本、結構、身分雜湊（`entry_id`）與欄位限制。
3. **差異比對分類**：
   - **新增詞條 (New)**：本機快照中尚不存在此 `entry_id` 的詞條。
   - **重複項目 (Duplicate)**：`entry_id` 與元資料完全相符者（無損保留，不重複累加統計次數）。
   - **衝突項目 (Conflict)**：**僅限於具有相同 `entry_id` 但附帶元資料（如 review 狀態、policy、source、annotation 等）不一致之情況**。
     > [!NOTE]
     > 依據交換契約，同讀音不同文字（同音字）或同文字不同讀音（多音字）各自具有完全獨立且唯一的 `entry_id`，均屬合法且有效之個別候選項目，**絕非衝突**，系統皆予以完整保留。
   - **不支援項目 (Unsupported)**：包含本版本尚未支援的欄位或格式（例如包含 `zh_aliases` 等未知欄位）。
4. **本機審核確認 (Approval) 與取消**：
   - 僅在使用者點選確認核准後，系統才以原子寫入（atomic write）儲存至本機獨立詞庫快照層。
   - 若使用者在預覽或審核過程中**取消 (Cancel)**，系統保證**不寫入任何資料 (writes nothing)**。

### 2.2 備份與回復機制 (Rollback & Backup)
- **不可變雜湊版本目錄與指標管理**：
  系統儲存層採用**以校驗雜湊命名之不可變版本目錄 (immutable checksum version directories)**，並透過 `current` 與 `previous` 指標進行原子切換。系統並非在每次匯入前複製暫存時間戳記備份檔，而是確保每個版本目錄皆具完整不可變性。
- **組字閒置邊界生效 (Idle Boundary Rollback)**：
  若使用者選取回復至前一版（`previous` 指標），**回復動作不會在使用者正在進行組字輸入（active composition）時立即切換**，以避免候選詞選取位置突變造成使用者困惑或輸入中斷；系統保證於組字結束後的**閒置邊界 (idle boundary)** 安全平順生效。

### 2.3 詞庫匯出 (Export)
- 使用者可隨時手動匯出本機共用詞庫快照為標準 UTF-8 JSON 交換檔。
- 匯出內容包含使用者已核准之詞條，亦可包含本機快照中保留的拒絕／觀測項目與完整元資料，但不混入輸入法系統底層辭典、正式新酷音個人詞庫或未授權的個人敲鍵歷史。

#### 2.3.1 工程詞條目匯出機制 (Engineering Export matching v1)
針對自訂工程詞庫（如技術詞、Unicode 映射、英文術語等）的匯出，v1 規範設有以下防護與操作規則：
1. **明確選取私人工程詞**：使用者必須在設定介面**明確勾選／選取欲匯出的私人工程詞條目 (explicitly select private engineering entries)**，系統不會未經選取擅自全數輸出。
2. **預設拒絕別名遺失 (Default Refuses `zh_aliases` Loss)**：若選取的工程詞包含中文別名（`zh_aliases`），由於跨平台 v1 交換規範尚未支援該欄位，系統**預設拒絕匯出**以防止資料非預期遺失。
3. **明確略過別名選擇機制 (Explicit Omission Opt-In)**：若使用者仍欲匯出為 v1 交換格式，必須勾選「明確略過別名」之選項。勾選時介面會**清楚列出將被省略的確切別名清單**；此操作**僅在匯出檔案中省略別名，本機原始工程詞與其別名絕對完好保留**。
4. **不支援項目阻擋全部匯出 (Unsupported Entries Block Entire Export)**：若選取範圍內包含任何不合規或不支援的項目（如超出規格長度、控制字元等），系統**直接阻擋整批匯出**，不進行部分截斷輸出。
5. **來源修訂版本檢查 (Source Revision Checked)**：匯出時系統會校驗來源資料之修訂版號（revision），確保匯出過程未受背景並行修改影響。
6. **目標檔案絕不覆寫 (Existing Export File Never Overwritten)**：匯出儲存目標若已存在同名檔案，系統**絕不自動覆寫 (never overwritten)**，必須由使用者另存新檔或手動變更檔名。
7. **暫無自動中文私人詞庫匯出**：目前版本僅限手動選取之工程詞與共用交換快照，**暫無自動匯出中文私人詞庫 (No automatic Chinese private dictionary export yet)**。

## 3. v1 規範限制與目前相容性缺口

目前 v1 規範（`schema_version: "1.0.0"`）存在跨平台相容性缺口，使用者在交換詞庫時請務必留意：

1. **中文別名 (`zh_aliases`) 欄位尚未納入 v1 規範**：
   - `zh_aliases` 規範定義為**精確完成之中文文字觸發詞 (exact completed Chinese text triggers)**（例如打出完整詞彙後觸發工程詞候選），**絕非注音讀音或簡拼縮寫 (NOT phonetic readings or abbreviations)**。
   - Mac v1 剖析器會嚴格拒絕包含未知欄位的 JSON 文件。
   - **系統行為**：若匯入或處理包含 `zh_aliases` 的資料，系統**必須明確回報不支援的資料遺失風險（Unsupported Loss）並拒絕靜默丟棄**，嚴禁擅自將別名塞入 `annotation` 或 `source`。
2. **大小寫與 Unicode 精確保留**：
   - 交換格式身分雜湊對大小寫與 Unicode 字元敏感（例如 `H2O` 與 `H₂O`、`FinFET` 與 `finfet` 視為完全不同身分）。本機詞庫會無損保留原始字串，不進行 NFKC 正規化或自動小寫化。
3. **中文詞完整注音與聲調要求**：
   - 中文詞條（`zh_phrase`）每字必須有一標準注音音節並附帶正確聲調（以連字號 `-` 分隔，例如 `ㄌㄟˇ-ㄐㄧㄥ`）。中文別名本身不是合法注音讀音，系統亦不透過 AI 盲目臆測補齊未核准音節。
